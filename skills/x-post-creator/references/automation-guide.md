# 定期実行・自動化ガイド

このドキュメントは、将来的にこのスキルを定期実行（スケジュールタスク）で自動化する際の設計指針です。

## 自動化の全体像

最終的な目標は、以下のフローを完全に自動化することです。

```
[定期トリガー] → [リサーチ] → [投稿案作成] → [レビュー/承認] → [X投稿]
```

## 定期実行時の処理フロー

### Phase 1: トレンドリサーチ（自動）
1. X上のトレンドトピック（AI、BtoBマーケティング、中小企業関連）を検索
2. 橋本氏のnote記事一覧を取得し、最新記事を確認
3. 競合アカウントの直近の投稿で伸びているものを分析

### Phase 2: 投稿案作成（自動）
1. リサーチ結果をもとに、SKILL.mdのワークフローに従って3件の投稿案を作成
2. 出力フォーマットに従ってMarkdownファイルとして保存

### Phase 3: レビュー・承認（手動 or 自動）
- **手動モード**: 作成した投稿案をユーザーに提示し、承認を得てから投稿
- **自動モード**: 事前に設定したルール（NGワードチェック、文字数チェック等）をパスしたら自動投稿

### Phase 4: X投稿（自動）
1. 承認済みの投稿案をX APIまたはブラウザ操作で投稿
2. 自己リプライ（リンク付き）を投稿
3. 投稿結果（URL、タイムスタンプ）をログに記録

## 投稿スケジュールの推奨設定

| 項目 | 推奨値 |
|---|---|
| 投稿頻度 | 1日1-2件（週5-10件） |
| 投稿時間 | 平日 7:30 / 12:00 / 18:30 |
| 投稿間隔 | 最低3-4時間空ける |
| バッチ作成 | 週初めに1週間分を一括作成 |

## 自動化に向けた準備事項

1. **X API認証**: X Developer Portalでアプリを作成し、OAuth 2.0の認証情報を取得
2. **投稿キュー**: 作成した投稿案をキューに入れ、スケジュールに従って順次投稿する仕組み
3. **パフォーマンス追跡**: 投稿後のインプレッション、エンゲージメント率を記録し、次回の投稿案作成にフィードバック
4. **A/Bテスト**: 同じトピックで異なる構成の投稿を試し、どのパターンが最も効果的かを検証
